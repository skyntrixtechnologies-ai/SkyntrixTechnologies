# Domain-migration E2E suite

Proves, through the real admin UI, that quotation/invoice/receipt PDFs
generated by this app show `https://www.skyntrixtechnologies.in/` and never
the retired `https://skyntrix.vercel.app/`.

## What's here

- `domain-migration.spec.js` — logs in, creates a quotation/invoice/receipt
  via the real forms, clicks the real **Download PDF** button, and inspects
  every page of the downloaded PDF. It also reproduces the specific
  stale-on-disk-cache bug that let the old domain survive the first domain
  fix: it overwrites the record's PDF file on disk with a synthetic
  "pre-fix" file (simulating a document generated before a config change)
  and clicks Download again, proving the app regenerates it instead of
  re-serving the stale copy.
- `static-domain-scan.spec.js` — supplementary static grep across source for
  the old hostname, distinguishing intentional references (this suite
  itself, docs) from live regressions.
- `utils/pdf.js` — `extractPdfPagesText(path)` (page-by-page text) and
  `extractLinkAnnotations(path)` (resolves PDFKit's Link annotations to
  their target URL, without needing a PDF rendering engine).

## Root cause this suite guards against

`server/controllers/{quotation,invoice,receipt}.controller.js`'s download
routes call `ensure{X}Pdf(doc)` - a cache wrapper that serves the existing
file on disk unless `{ force: true }` is passed. The download routes
(and the WhatsApp follow-up handlers in `whatsappWebhook.controller.js`)
were calling it with no `force` flag, so **any record whose PDF had already
been generated before a COMPANY-config change (like this domain migration)
kept re-serving the old file forever**, regardless of how many times the
generator code itself was fixed. All five call sites now force regeneration.

## Running it

This suite does **not** auto-start the app (it needs a running local
MongoDB, which the client/server workspaces don't manage). Start them
yourself, pointed at a local/test database - never at production:

```bash
# 1. MongoDB running locally, then seed a local test admin:
npm run seed -w server

# 2. Backend (uses server/.env - keep MONGODB_URI local):
npm run dev -w server

# 3. Frontend - override VITE_API_URL so it talks to the LOCAL backend
#    through the Vite proxy instead of whatever production URL
#    client/.env.development may have baked in:
cd client && VITE_API_URL=/api npx vite

# 4. Point Playwright at whatever origin step 3 printed, then run:
PLAYWRIGHT_BASE_URL=http://localhost:5173 npx playwright test
```

Reports/traces land in `tests/e2e/.output/` (gitignored); downloaded PDFs
land in `tests/e2e/.output/downloads/`.

Login uses `SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD` (same ones `server/utils/seed.js`
creates locally) - never real credentials, never printed by the tests.
